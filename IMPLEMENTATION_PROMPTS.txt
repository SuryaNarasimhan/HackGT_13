PHASE 1: ENVIRONMENT & CORE MATH ENGINE
================================================================================

[PROMPT 1.1: Scaffolding, Dependencies & Emotion Taxonomy]
--------------------------------------------------------------------------------
Let's start Phase 1 of SocialLens. Please:
1. Create a requirements.txt with all necessary dependencies:
   - soundcard
   - numpy
   - scipy
   - faster-whisper
   - transformers
   - torch
   - mss
   - opencv-python
   - PyQt6
   - google-genai
   - python-dotenv
   - pytest
2. Create the project directory structure as specified in PROJECT_PLAN.md:
   - app/
     - capture/
     - pipelines/
     - math_engine/
     - agent/
     - ui/
       - components/
   - tests/
   - assets/
3. Implement app/config.py for global settings (sample rates, buffer sizes, JSD threshold tau=0.45, model names, API keys).
4. Implement app/pipelines/taxonomy.py defining the canonical 7-emotion discrete simplex ('joy', 'surprise', 'sadness', 'anger', 'disgust', 'fear', 'neutral'), including helper functions for vector validation, label indexing, and softmax normalization.


[PROMPT 1.2: Multi-Distribution Jensen-Shannon Divergence (JSD) & Unit Tests]
--------------------------------------------------------------------------------
Now let's build the mathematical core in app/math_engine/jsd.py:
1. Implement the generalized Jensen-Shannon Divergence for three discrete distributions (P_v, P_a, P_s) using base-2 logarithm so the output is strictly bounded between [0, 1].
2. Include epsilon-clamping (1e-12) for numerical stability to prevent log2(0) or division-by-zero errors.
3. Add pairwise JSD calculation functions to identify which specific modalities conflict the most (e.g., Words vs. Tone, Words vs. Face).
4. Create tests/test_jsd.py with pytest unit tests verifying:
   - Identical distributions yield JSD = 0.0.
   - Completely disjoint orthogonal distributions yield maximum divergence approaching 1.0.
   - Symmetry: permuting the order of distributions does not change the resulting score.
   - Edge cases: uniform distributions, zero-prob elements, and boundary values.
5. Run the unit tests via terminal and confirm they all pass.

PHASE 2: COGNITIVE REASONING ENGINE (GEMINI 2.5 FLASH)
================================================================================

[PROMPT 2.1: Gemini Reasoning Agent & Structured Schema]
--------------------------------------------------------------------------------
Let's implement the cognitive reasoner in app/agent/gemini_reasoner.py:
1. Use the new google-genai SDK targeting gemini-2.5-flash with structured JSON response mode (response_mime_type="application/json").
2. Define a strict output schema returning:
   - social_cue_type (e.g., "Dry Sarcasm / Irony", "Playful Teasing", "Concealed Frustration", "Polite Agreement", "Understated Humor", "Ambiguous")
   - confidence ("High", "Medium", "Low")
   - explanation (1-2 sentences explaining why the cross-modal mismatch indicates this cue)
   - suggested_action (practical, supportive advice on how to respond)
3. Write an empathetic prompt instructing the model to translate cross-modal incongruence into assistive, non-accusatory advice for a neurodivergent user.
4. Add a graceful fallback/mock mode so the application still functions smoothly if the GEMINI_API_KEY is missing or the machine is offline.
5. Create a test script tests/test_gemini_reasoner.py that simulates a deadpan sarcasm scenario, calls the reasoner, and prints the parsed structured JSON response.


================================================================================
PHASE 3: THE THREE INDEPENDENT PERCEPTION PIPELINES
================================================================================

[PROMPT 3.1: Semantic Pipeline (STT + Text Emotion)]
--------------------------------------------------------------------------------
Let's implement the Semantic Pipeline in app/pipelines/semantic_pipeline.py:
1. Use faster-whisper (model size "base.en") to transcribe incoming audio buffers into text with timestamps and confidence.
2. Use a fast pre-trained Hugging Face emotion classifier (e.g., "j-hartmann/emotion-english-distilroberta-base") to classify the transcribed text into an emotion distribution.
3. Project the model's raw output probabilities into the canonical 7-emotion simplex via taxonomy.py.
4. If the transcript is empty or pure silence/noise, return a fallback neutral distribution.
5. Create a test script tests/test_semantic_pipeline.py that feeds a sample text string (e.g., "Oh wow, that's just fantastic news.") and verifies the 7-D probability vector output.


[PROMPT 3.2: Audio Acoustic/Prosody Pipeline]
--------------------------------------------------------------------------------
Let's implement the Audio Prosody Pipeline in app/pipelines/audio_pipeline.py:
1. Ingest raw 16kHz mono audio waveform segments.
2. Extract acoustic tone emotion using a lightweight pre-trained audio emotion model (e.g., "superb/hubert-base-superb-er" or "ehcalabres/wav2vec2-lg-xlsr-en-speech-emotion-recognition") OR acoustic prosody feature extraction (pitch variance, energy contour, jitter, speech rate).
3. Project the predicted probabilities into the canonical 7-emotion simplex.
4. Include heuristic checks (e.g., detecting flat monotone pitch with low variance indicating deadpan delivery).
5. Create a test script tests/test_audio_pipeline.py that tests synthetic/sample audio waveforms (flat monotone vs. high-pitched excited) and verifies the 7-D probability distribution output.


[PROMPT 3.3: Video Perception Pipeline]
--------------------------------------------------------------------------------
Let's implement the Video Pipeline in app/pipelines/video_pipeline.py:
1. Receive RGB frame crops of the speaker's face from screen capture.
2. Use OpenCV Haar Cascades / MediaPipe / lightweight face detector to extract the face bounding box.
3. Classify facial emotion into the canonical 7-emotion simplex using an ONNX facial emotion model or DeepFace/FER backend.
4. Aggregate predictions across 3-5 sampled keyframes over the utterance window by averaging the probability vectors.
5. Graceful fallback: If no face is detected (camera off or occluded), return a uniform neutral distribution with a "face_detected=False" flag.
6. Create tests/test_video_pipeline.py to verify inference on a sample face image.


================================================================================
PHASE 4: CAPTURE & VOICE ACTIVITY DETECTION (VAD)
================================================================================

[PROMPT 4.1: Audio Loopback & Silero VAD Ingestion]
--------------------------------------------------------------------------------
Let's implement the audio capture and speech segmentation:
1. In app/capture/audio_loopback.py, use the soundcard library to capture Windows default speaker loopback (WASAPI) continuously into a thread-safe circular buffer holding the last 8 seconds of 16kHz mono audio.
2. In app/capture/vad_detector.py, integrate Silero VAD (torch/onnx) to monitor incoming audio chunks in real time.
3. Detect speech start and speech end. Trigger an "utterance complete" event when speech is followed by >= 500ms of silence.
4. Slice the corresponding audio segment from the buffer and emit it to a callback function for downstream pipeline processing.
5. Create a test script tests/test_audio_capture.py that records 5 seconds of system audio and prints VAD speech intervals.


[PROMPT 4.2: Screen Capture & Speaker Region Cropping]
--------------------------------------------------------------------------------
Let's implement the screen capture system in app/capture/screen_capture.py:
1. Use the mss library to capture a specified screen region or monitor coordinates at 30+ FPS with low CPU overhead.
2. Maintain a ring buffer of recent frames timestamped to align with the audio stream.
3. Provide a simple calibration utility or interactive selector allowing the user to select the bounding box of the speaker's video tile on Zoom/Teams/Meet.
4. Create tests/test_screen_capture.py to test grabbing frames and saving a test screenshot to disk.
